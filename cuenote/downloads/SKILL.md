# CueNote 행사 MD 작성 규칙

CueNote 는 마크다운 한 파일을 **행사 단계(장면)** 목록으로 바꿔, 현장에서 단계별 원고·슬라이드·타이머로 진행하는 앱입니다.
이 규칙대로 쓴 `.md` 를 앱의 **MD 파일 불러오기**로 올리면 바로 홈 화면의 전체 일정과 각 단계가 만들어집니다.

## 1. 출력 규칙 (가장 중요)

- **마크다운 본문만** 출력합니다. 설명 문장, 인사말, 코드 펜스(```)로 감싸기 금지. (대화로 기획할 때는 9절의 형식을 따릅니다)
- 원본 문서를 변환할 때는 원본에 없는 내용(멘트, 시간, 담당자)을 **지어내지 않습니다.** 모르는 값은 비워 둡니다. (대화로 새로 기획할 때는 9절)
- 사회자·연사 멘트는 원문 문장을 그대로 옮깁니다. 요약하지 않습니다.
- 시간은 `MM:SS`(예: `05:00`) 또는 `H:MM:SS` 로 씁니다.

## 2. 문서 구조

```
---
title: 행사 이름
date: 2026-12-05
venue: 장소
start: 14:00
---

# 준비 사항
- [ ] 리허설 전 체크 항목

# 본행사 일정
| 시간 | 순서 | 내용 | 담당 |
| :--: | --- | --- | --- |
| 14:00 | 개회 | 개회 선언 | 사회자 |

# 본행사 시나리오

## 개회 선언 {time: 05:00, color: blue, bgm: 오프닝, cam: CAM1}
- **사회자**: 지금부터 기념식을 시작하겠습니다.
> [음향 큐] 팡파르 후 음악 페이드아웃

## 인사말 — 대표이사 {time: 10:00, color: amber, mic: 단상 마이크, who: 대표이사}
- **사회자**: 대표이사님의 인사말이 있겠습니다.

존경하는 내빈 여러분, …(원고 문단 그대로)

## 발표 — 사업 비전 {time: 20:00, color: green, type: slides}
- **사회자**: 발표가 있겠습니다.
### 1. 지난 성과
- 핵심 내용
### 2. 앞으로의 비전
- 핵심 내용
```

### 프론트매터 (`---` 사이, 선택)
| 키 | 의미 | 예 |
| --- | --- | --- |
| `title` | 행사 이름 (홈 화면 제목) | `창립 30주년 기념식` |
| `date` | 날짜 | `2026-12-05` |
| `venue` | 장소 | `그랜드볼룸` |
| `start` | 본행사 시작 시각 → 각 단계 예정 시각 자동 계산 | `14:00` |
| `mode` | **부분 수정 문서일 때만** `partial` | `partial` |
| `flow` | 단계 끝에서 홈을 거치지 않고 **바로 다음 단계로** 넘길 때 `연속` (발표처럼 슬라이드 한 장 = 한 단계일 때) | `연속` |

### 단계(장면)
- `# 제목` 또는 `## 제목` 한 줄이 **한 단계**입니다. `---` 수평선으로도 나눌 수 있습니다.
- **섹션**: 본문 없는 `# 섹션명` 바로 아래에 `## 단계`들을 두면 홈 화면에서 섹션으로 묶입니다. (예: `# 본행사 시나리오` → `## 개회`, `## 인사말`)
- 제목 끝 `{키: 값, 키: 값}` 에 속성을 씁니다.

| 속성 | 의미 | 값 |
| --- | --- | --- |
| `time` | 배정 시간 (타이머) | `05:00`, `10:00`, `1:30:00` |
| `color` | 단계 색 | `blue` `red` `green` `amber` `purple` `pink` `cyan` `slate` |
| `type` | `slides` 이면 슬라이드 발표 (아래 5절) | `slides` |
| `at` | 이 단계의 지정 시작 시각 | `14:25` |
| `who` | 담당·연사 | `대표이사` |
| `bgm` `cam` `mic` `light` `vtr` 등 | 기술 큐 뱃지 (자유 키) | 자유 텍스트 |
| `remove` | 부분 수정에서 이 단계 삭제 | `true` |

색 가이드: 개회·폐회 `blue`/`cyan`, 인사말·축사 `amber`/`purple`, 발표 `green`, 시상·공연 `pink`, 준비·안내 `slate`, 긴급·주의 단계 `red`.

## 3. 본문 요소

| 쓰는 법 | 앱 표시 |
| --- | --- |
| `- **사회자**: 멘트` | 대본 줄. `**굵게**` 는 화자·키워드 강조 |
| 일반 문단 | 인사말·나레이션 원고 (스크롤로 넘김) |
| `- [ ] 항목` | 터치 체크리스트 (준비 사항) |
| `> [음향 큐] 내용` | 연출 큐 박스. 라벨 예: `[음향 큐]` `[조명 큐]` `[영상 큐]` `[연출 큐]` |
| `> [주의] 내용` | 노란 주의 박스 (`주의`·`경고`·`긴급`·`필수` 라벨) |
| `### 소제목` | 소제목 (슬라이드 단계에서는 슬라이드 구분) |
| 마크다운 표 | 일정표 |

## 4. 인사말·축사·나레이션

- 사회자 소개 멘트는 `- **사회자**: …` 로, 연사 원고 본문은 **일반 문단**으로 씁니다.
- 원고는 문단 단위로 빈 줄을 두어 나눕니다. 앱에서 화살표로 한 화면씩 넘깁니다.
- 원고 중 연출 지시는 `> [연출 큐] …` 로 분리합니다.

## 5. 슬라이드 발표 (`type: slides`)

- 발표 단계에 `{type: slides}` 를 붙이고, 슬라이드마다 `### 슬라이드 제목` 으로 나눕니다.
- 첫 `###` 앞의 내용(사회자 소개, 큐)은 도입 화면이 됩니다.
- 각 슬라이드에는 발표자 노트(핵심 문장, 목록)를 씁니다. 앱에서 화살표 한 번 = 슬라이드 한 장.
- 슬라이드마다 시간·연사를 따로 관리해야 해서 **슬라이드 한 장을 한 단계(`##`)로** 쓰는 발표 시나리오라면, 프론트매터에 `flow: 연속` 을 넣습니다. 앱에서 단계 끝의 "다음" 이 홈을 거치지 않고 다음 슬라이드(단계)로 바로 넘어갑니다.

## 6. 전체 등록 vs 부분 수정

**전체 등록**: 위 구조 전체를 씁니다. 앱에서 새 행사로 등록되거나 기존 행사를 대체합니다.

**부분 수정**: 프론트매터에 `mode: partial` 을 넣고 **바뀌는 단계만** 씁니다.
- 기존 단계와 **제목이 같으면 교체**됩니다. (`[Scene 3]` 같은 접두어·띄어쓰기·문장부호는 무시하고 비교)
- 기존에 없는 제목이면 **추가**됩니다. `# 섹션명` 아래에 두면 그 섹션 끝에 들어갑니다.
- 삭제할 단계는 `# 제목 {remove: true}` 한 줄만 씁니다.
- 프론트매터의 다른 값(`date`, `venue` 등)도 함께 갱신됩니다.

```
---
mode: partial
---

# 본행사 시나리오

## 축사 — 협회장 {time: 05:00, color: purple, mic: 단상 마이크}
- **사회자**: (수정된 소개 멘트)

## 경품 추첨 {time: 08:00, color: pink}
- [ ] 추첨함 무대 좌측 배치
- **사회자**: 경품 추첨을 진행하겠습니다.

# 장기근속 시상 {remove: true}
```

## 7. 원본 문서에서 변환할 때

1. **식순표/시간표** → `start` 와 각 단계의 `time` 을 계산합니다. (다음 순서 시작 − 현재 시작) 계산할 수 없으면 `time` 을 비웁니다.
2. **담당·연사** → `who` 속성, **음향·영상·조명·카메라 지시** → 해당 키 속성 또는 `> [○○ 큐]` 박스.
3. **사회자 대본** → 순서마다 단계를 만들고 멘트를 `- **사회자**: …` 로 옮깁니다.
4. **인사말·축사 원고** → 해당 단계 본문에 문단 그대로.
5. **발표 자료(PPT 개요)** → `type: slides` 단계, 슬라이드마다 `###`.
6. **준비물·체크리스트** → `# 준비 사항` 단계의 `- [ ]` 항목.
7. 원본의 전체 일정표는 `# 본행사 일정` 단계에 표로 그대로 둡니다. (선택)

## 8. 출력 전 점검

- [ ] 코드 펜스 없이 마크다운만 출력했는가
- [ ] 단계마다 `#`/`##` 제목이 있고, 속성 `{…}` 이 제목 줄 끝에 있는가
- [ ] 시간은 `MM:SS` 형식인가, 모르는 시간은 비웠는가
- [ ] 멘트·원고를 지어내거나 요약하지 않았는가
- [ ] 부분 수정이면 `mode: partial` 이 있고, 교체할 단계 제목이 기존과 같은가

## 9. 대화로 행사 기획하기

사용자가 문서 없이 "토요일 18시 송년회, 2시간, 대표 인사·시상·경품 추첨" 처럼 말로 행사를 설명하면, 대화하며 계획을 함께 만듭니다.

**대화 방식**
- 정보가 조금이라도 있으면 질문을 길게 하지 말고 **바로 초안을 보여 줍니다.** 행사 성격·시작 시각·전체 시간이 전혀 없을 때만 짧게 1~3가지 묻습니다.
- 계획을 만들거나 고칠 때마다: 무엇을 했는지 1~3문장으로 설명한 뒤, ` ```cuenote ` 코드 블록 **하나에 완성된 전체 행사 MD** 를 넣습니다. 앱은 이 블록을 찾아 [새 행사로 등록] 버튼을 띄웁니다.
- 고칠 때도 일부만 쓰지 말고 처음부터 끝까지 전체를 다시 씁니다. 질문만 할 때는 코드 블록을 쓰지 않습니다.
- 이미 등록된 행사를 대화로 고칠 때는 6절의 **부분 수정 MD**(`mode: partial`)를 ` ```cuenote ` 블록에 넣습니다.

**초안 작성 원칙** (이 절에서는 1절의 "지어내지 않기"보다 우선)
- 사회자 멘트, 인사말·나레이션 원고, 준비 사항, 연출 큐를 행사 성격에 맞게 초안으로 써도 됩니다.
- 사용자가 말한 사실(이름·날짜·시각·숫자·순서)은 바꾸지 않습니다. 모르는 사람·회사 이름은 `○○○` 로 둡니다.
- 전체 시간이 주어지면 각 단계 `time` 의 합이 그 시간과 맞게 배분하고, 시작 시각은 프론트매터 `start` 에 씁니다.
- 준비물은 `# 준비 사항` 체크리스트, 본 순서는 `# 본행사 시나리오` 아래 `##` 단계, 발표는 `type: slides` + `###` 로 씁니다.
- 발표 하나만 슬라이드 단위 단계로 나눈 시나리오(발표 리허설 등)는 프론트매터에 `flow: 연속` 을 넣습니다.

**예시 응답**

> 토요일 18시부터 2시간 송년회 계획을 만들었습니다. 경품 추첨은 공연 뒤에 두었어요.
>
> ` ```cuenote `
> ---
> title: 2026 송년회
> start: 18:00
> ---
>
> # 본행사 시나리오
>
> ## 개회 {time: 05:00, color: blue}
> - **사회자**: …
> ` ``` `
